## 3. 판정 원칙

1. 법원이 인정한 사실(범죄사실, 양형이유에서 인정한 내용)만 근거로 한다. 공소사실에만 있고 법원이 인정하지 않았거나, 어느 범행에 속하는지 불분명한 내용은 9로 코딩한다.
2. 코드는 1(해당), 0(판결문에 기재 없음), 9(기재는 있으나 판단 불가)로 한다.
3. 한 범행에 수단과 요구가 여러 개 있을 수 있다. 해당하는 것을 모두 1로 코딩한다.
4. 1로 코딩한 항목은 반드시 근거 문장을 판결문에서 그대로 옮겨 적는다. 요약이나 추론으로 대신하지 않는다.
5. 판결문에 쓰이지 않은 의도나 목적을 추측하여 코딩하지 않는다. 요구는 판결문에 요구 내용이 드러나 있을 때만 1이다.

## 4. 변수

### 4.1 수단(무엇으로 압박했는지)

| 코드명 | 수단 | 판정 기준 | 예 |
|---|---|---|---|
| M_threat | 위협·겁주기 | 생명·신체 위해 고지, 흉기 제시, 물건 파손, 폭언·고함, 자해·자살 위협 등으로 겁을 줌 | "죽여버리겠다", 칼을 들고 위협, 휴대폰을 부숨 |
| M_reputation | 평판·유포 위협 | 촬영물·사생활을 유포하거나 주변에 알리겠다고 위협하거나 실제로 유포함 | "나체사진을 뿌리겠다", 지인에게 사생활 폭로 |
| M_emotional | 정서적 학대 | 모욕, 비하, 죄책감 유발, 가스라이팅 | 반복적 욕설 메시지, "너 때문에 내 인생이 망했다" |
| M_physical | 신체 폭력·강제력 | 폭행, 상해, 붙잡기·끌고 가기 등 물리력 행사 | 폭행, 손목을 잡고 끌어냄 |
| M_surveil | 감시·추적 | 위치추적, 미행, 집·직장 앞 대기, 행적 확인 | 위치추적앱 설치, 귀가 시간에 집 앞 대기 |
| M_account | 계정·기기 침해 | 비밀번호 요구, 계정 무단 접속, 휴대폰 검열 | 휴대폰 잠금 해제 요구, 메신저 열람 |
| M_contact | 반복 연락·접근 | 거부 의사 이후에도 반복해서 연락하거나 찾아감 | 하루 수십 회 전화, 차단 후 다른 번호로 연락 |
| M_economic | 경제적 압박 | 카드·통장 회수, 생활비 차단, 금전 갈취, 채무 강요 | 카드를 빼앗음, 피해자 명의 대출 강요 |
| M_thirdparty | 제3자 이용 | 자녀, 가족, 지인, 직장을 통해 압박 | 피해자 부모에게 연락해 압박 |
| M_other | 기타 | 위에 없는 수단. 내용을 기재 | |

각 수단에 대해 경로를 따로 코딩한다.

- `{수단}_dig`: 메시지, 전화, SNS, 위치추적앱, 촬영물 전송 등 디지털 경로로 이루어졌으면 1
- `{수단}_off`: 직접 찾아오거나 대면하여 이루어졌으면 1
- 두 경로가 모두 쓰였으면 둘 다 1로, 판결문으로 경로를 알 수 없으면 둘 다 9로 코딩한다.
- 해당 수단이 0이면 경로 칸은 비워 둔다.

### 4.2 요구(무엇을 얻어내려 했는지)

| 코드명 | 요구 | 판정 기준 | 예 |
|---|---|---|---|
| D_relation | 관계 유지·재결합 | 이별 철회, 재결합, 관계 지속 요구 | "다시 만나자", "헤어지면 가만두지 않겠다" |
| D_contact | 만남·연락 응답 | 만남, 전화 받기, 차단 해제, 답장 요구 | "차단 풀고 전화해" |
| D_isolation | 인간관계 차단 | 특정인과의 만남·연락 금지 | "친구 만나지 마" |
| D_movement | 이동·외출·거주 | 외출 금지, 귀가 강요, 거주지 이전 강요 또는 금지 | "당장 집으로 들어와" |
| D_money | 금전·재산 | 돈, 재산, 명의 제공 요구 | 돈을 보내라고 요구 |
| D_report | 신고·처벌 철회 | 고소 취하, 처벌불원서 작성, 진술 번복, 신고 저지 | "고소 취하하지 않으면 유포하겠다" |
| D_sexual | 성적 요구 | 성관계, 촬영 등 성적 행위 요구 | |
| D_work | 일·학업 | 퇴사, 휴학, 출근·등교 방해 관련 요구 | "회사 그만둬" |
| D_report_info | 행적·정보 보고 | 위치, 동행인, 일정 보고 요구 | "지금 어디서 누구랑 있는지 사진 찍어 보내" |
| D_other | 기타 | 위에 없는 요구. 내용을 기재 | |

### 4.3 결합 여부

| 코드명 | 판정 기준 |
|---|---|
| link | 1: 수단이 요구를 관철하기 위한 조건이나 대가로 쓰였음. "~하지 않으면 ~하겠다", "~할 때까지 ~하겠다"처럼 명시적이거나, 요구 직후 위협하는 등 판결문 서술상 연결이 분명한 경우<br>0: 수단과 요구 중 하나만 있거나, 둘 다 있어도 서로 연결되지 않음<br>9: 연결 여부를 판결문으로 판단할 수 없음 |
| link_pairs | link=1이면 결합된 수단과 요구 쌍을 기재. 예: `M_reputation+D_relation; M_threat+D_report` |

### 4.4 파생 변수

- cc_event_detail: link=1이면 결합(1), link=0이고 수단 하나 이상 1이면 수단만(0), 수단·요구 모두 명시적 0이면 해당없음(0), 그 외 판정불가(9).
- `n_means`: 1로 코딩된 수단 수
- `n_demands`: 1로 코딩된 요구 수

### 4.5 근거

- `evidence_means`: 수단별 근거 문장 원문
- `evidence_demand`: 요구별 근거 문장 원문
- `evidence_link`: 결합 판정의 근거 문장 원문
- `coder_note`: 판단이 애매했던 이유, 9로 코딩한 이유

## 5. 판정 예시

1. "피고인은 피해자가 이별을 통보하자 '다시 만나주지 않으면 네 나체 사진을 가족에게 보내겠다'는 메시지를 보냈다."
   → M_reputation=1(dig=1, off=0), D_relation=1, link=1, cc_event=1
2. "피고인은 말다툼 중 피해자에게 욕설을 하며 휴대폰을 바닥에 던졌다."
   → M_threat=1(dig=0, off=1), M_emotional=1(dig=0, off=1), 요구 없음, link=0, cc_event=0
3. "피고인은 피해자의 귀가를 지켜보고 반복적으로 만나자고 요구하며 차량을 막았다."
   → M_surveil=1(off=1), M_physical=1(off=1), D_contact=1, link=1, cc_event=1
4. "피고인은 피해자가 고소하자 '취하하지 않으면 회사에 다 알리겠다'고 전화했다."
   → M_reputation=1(dig=1), D_report=1, link=1, cc_event=1
5. 공소사실에는 협박이 있으나 법원이 무죄로 판단한 부분
   → 해당 수단은 9, coder_note에 이유 기재


row_type: 해당 차수의 행위가 본문에 특정되면 본문(공소사실 본문 포함); 별지에서만 특정되면 별지. 포괄기간 자체를 서술한 본문과 개별 날짜를 구분. 법원 인정 여부는 별개. 수단=9이면 경로 9/9. 동기·피해자의 요구를 가해자의 요구로 바꾸지 말 것. 같은 차수의 모든 장면을 확인하고 다른 차수의 요구를 옮기지 말 것. 0은 현실의 부재가 아니라 판결문상 미기재.
